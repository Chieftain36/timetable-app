# Полное руководство по проверке спринтов 4–5

Версия кода: 15ccf86; ветка feat/sprints-4-5. Дата: 03.11.2026.

42 контрольных сценариев. Статусы ручной проверки заполняются после выполнения.

## 1. Как пользоваться руководством

Это руководство для ручной приёмки US16–US25 в University Timetable Generator. Оно относится к коду коммита 15ccf86 в ветке feat/sprints-4-5. Названия кнопок приведены по английскому интерфейсу. Руководство не означает, что каждый приведённый ручной сценарий уже выполнен в вашей установке.

- Сначала подготовьте отдельную тестовую установку и данные из разделов 3–7.
- Пройдите базовую генерацию, блокировку и публикацию. Затем проверяйте личные страницы и негативные сценарии.
- Для каждой проверки запишите фактический результат, статус и доказательство. Пустой чек-лист в конце предназначен для заполнения.
- Не переходите к разрушительным/ошибочным сценариям на рабочей университетской базе. Используйте только тестовые данные.
- На полный ручной цикл закладывайте примерно 90–150 минут; автоматические проверки выполняются отдельно.

| Статус | Когда ставить |
| --- | --- |
| PASS | Все ожидаемые результаты подтверждены. |
| FAIL | Выполнены условия, но хотя бы один ожидаемый результат нарушен. |
| BLOCKED | Проверку нельзя провести: нет роли, данных, миграции или инструмента. |
| NOT RUN | Проверка ещё не выполнялась. |
| SKIPPED | Автотест явно пропущен; это не PASS. |

> Скриншоты, записи API и логи не должны содержать пароли, JWT, содержимое .env или персональные данные. Учебные email из этого руководства вымышлены.

Для ролей используйте разные профили браузера или отдельные приватные окна. Несколько обычных вкладок одного профиля разделяют localStorage: вход в другой аккаунт может изменить сессию в соседней вкладке.

Рабочий черновик хранится в schedules. Публикация — отдельный неизменяемый снимок с сохранёнными названиями, временем и сроком действия. Изменение или генерация черновика не должны менять уже опубликованную копию.

Расписание повторяется по дням недели. Teaching period задаёт включительные границы периода. Две недели внутри одного периода могут содержать одинаковые занятия; это ожидаемо. Перенос отдельного занятия только на конкретную дату и восстановление старой версии не входят в этот спринт.

> Генератор — детерминированный жадный алгоритм с ограничениями, а не обученная AI/ML-модель. Качество ниже 100 не означает нарушение жёстких правил; глобальный оптимум не гарантируется.

## 3. Подготовка установки и запуск

Нужен полный проект из feat/sprints-4-5: index.html, main.py, planning.py, database.py, models.py, scheduler.py, schema.sql, compose.yaml и зависимости. Замены одного index.html недостаточно.

- Скачайте ветку на GitHub: Code → Download ZIP. Распакуйте в отдельную папку для проверки.
- Установите и запустите Docker Desktop с Linux containers.
- Откройте PowerShell в папке, содержащей compose.yaml.
- Для новой установки выполните команду ниже и дождитесь готовности контейнеров.

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1
docker compose ps
docker compose logs --tail=50 app db
```

Откройте http://localhost:8000. API-документация: http://localhost:8000/docs. При первом запуске start.ps1 создаёт приватный .env. Логин bootstrap-администратора по умолчанию admin@example.com; пароль берите локально из BOOTSTRAP_ADMIN_PASSWORD. Не копируйте его в отчёт.

### ENV-01 · Общее · Сервер, база и вход администратора

**Роль:** admin

**Условия:** Новая тестовая установка; Docker работает.

**Действия:**
1. Проверьте docker compose ps: база и приложение запущены; база здорова.
2. Откройте сайт и войдите администратором.
3. Откройте Weekly timetable, Users, Rooms и Generate timetable.

**Ожидаемый результат:**
- Нет отказа соединения, пустого белого экрана и сообщения о недостающей миграции.
- Видны административные разделы, а Generate timetable открывает новый рабочий экран, не только старое поле UUID.

**Доказательство:** Скриншот меню, вывод compose ps без секретов.

## 4. Обновление существующей тестовой базы

> Этот раздел нужен только для существующей установки на предыдущей версии. Сохраните .env и том базы. Перед обновлением создайте приватную резервную копию обычным способом. Не используйте docker compose down -v: команда удаляет данные.

Приложение не применяет миграцию автоматически. Новая база получает таблицы из schema.sql; существующая требует migrations/004_planning.sql. Команды ниже меняют выбранную базу: выполняйте их только на своей тестовой копии или после отдельного разрешения на обновление.

```powershell
docker compose stop app
docker compose up -d db
Get-Content -Raw .\migrations\004_planning.sql |
  docker compose exec -T db psql -U timetable -d timetable -v ON_ERROR_STOP=1
if ($LASTEXITCODE -ne 0) { throw 'Migration failed' }
docker compose up --build -d app
```

Скрипт добавляет настройки, связи студентов с группами, правила аудиторий, блокировки, версии и даты периода. Он не публикует расписание и не выбирает группы студентам. Для более старой схемы сначала отдельно проверьте совместимость с предыдущими обновлениями.

### ENV-02 · Общее · Обновление не теряет данные

**Ожидаемый результат:**

- Новые разделы доступны. Студентам ещё нужно назначить группы; официальная версия сама не появляется.

**Доказательство:** Сводка «до/после», результат миграции, без содержимого .env.

## 7. Доступность, нагрузка и учебный период

Войдите T1 в отдельном профиле браузера. В My availability задайте Monday 08:00 и Tuesday 08:00 как Unavailable, Monday 10:00 как Preferred, остальные слоты как Available. Кнопка слота циклически меняет состояние Available → Unavailable → Preferred. При лимите блокировок сначала задавайте Preferred, затем остальные Unavailable. Сохраните изменения. T2 оставьте все слоты Available; если ничего не меняли, отдельное сохранение может не требоваться.

| Курс | Группа | Преподаватель | Режим | Раз/нед. | Мин. |
| --- | --- | --- | --- | --- | --- |
| P | A | T1 | practice | 2 | 60 |
| P | B | T1 | practice | 2 | 60 |
| L | A | T2 | lecture | 2 | 60 |
| L | B | T2 | lecture | 2 | 60 |

Создайте четыре строки в Teaching loads. Итого ожидается 8 занятий: по 4 у каждой группы и каждого преподавателя, по 2 на сочетание курса и группы. Продолжительность 60 минут должна совпадать с реальными слотами.

В Generate timetable → Hard room rules: для P выберите Practical и required feature computer-lab; для L — Lecture без признаков. Нажмите Save room requirements. В Teaching period задайте понедельник текущей недели и воскресенье следующей недели; нажмите Save teaching period. Для 3 ноября 2026 пример: 2026-11-02 — 2026-11-15.

> Пустые даты означают неограниченный повторяющийся шаблон. Для проверки пустой недели нужен ограниченный период. Опубликованная версия сохраняет собственную копию дат; позднее изменение дат черновика не меняет старую публикацию.

## 10. US16: ошибки исходных требований

### GEN-03 · US16/18 · Нет подходящей аудитории

**Роль:** admin

**Условия:** Сохранён корректный черновик из 8 занятий.

**Действия:**
1. Создайте временную активную группу QA-S45-LARGE на 40 студентов.
2. Добавьте ей нагрузку: P, T1, practice, 1 занятие, 60 минут.
3. Повторите генерацию и сравните черновик с исходным.

**Ожидаемый результат:**
- Генерация завершена ошибкой с причиной отсутствия подходящей аудитории; A1 не подставляется вместо practical.
- Не сохраняется частичный результат: прежние 8 занятий и их ID остаются.
- Не создаётся успешная новая draft-версия.

**Доказательство:** Сообщение ошибки и контрольные ID до/после.

**После проверки:** Удалите временную нагрузку через Teaching loads; исходную группу и остальные нагрузки не меняйте.

### GEN-04 · US16 · Несовместимая продолжительность

**Роль:** admin

**Условия:** Исходная нагрузка снова восстановлена.

**Действия:**
1. Временно измените продолжительность одной нагрузки с 60 на 59 минут.
2. Если сама форма нагрузки отклоняет сохранение, зафиксируйте это как раннюю валидацию.
3. Если нагрузка сохранена, запустите генерацию.

**Ожидаемый результат:**
- Невалидное требование отклонено на этапе сохранения либо генерации: нет подходящего слота длительности 59.
- Рабочий черновик не заменён частично.

**Доказательство:** Место отказа и текст ошибки.

**После проверки:** Верните 60 минут и убедитесь, что корректная генерация снова возможна.

Условие «вообще нет нагрузок» удобнее проверять на новой тестовой базе. Не удаляйте действующие записи лишь ради этого теста в общем наборе. Ожидается понятное сообщение Add at least one active teaching load or assignment, а не успешный пустой результат.

### PUB-04 · US20/25 · Изменения черновика не меняют официальную копию

**Ожидаемый результат:**
- До явной публикации у S1 прежние 4 занятия; новая публикация меняет его группу на 5.

**Доказательство:** Сравнение Draft/Published и личной страницы до/после.

**После проверки:** При необходимости верните нагрузку к 2, перегенерируйте и опубликуйте финальное базовое состояние.

## 24. Ошибки: как отличить установку от дефекта

| Симптом | Что проверить / действие |
| --- | --- |
| Сайт не открывается | Docker Desktop, compose ps, app/db logs; это не доказательство ошибки генератора. |
| Новые разделы отсутствуют | Правильная ветка, полный проект, rebuild app; обновление одного HTML недостаточно. |
| Planning schema is not installed / 503 | Для существующего тома применена ли 004_planning.sql? Init schema.sql не повторяется сам. |
| Нет слотов/нагрузок | Созданы и активны ли записи? Длительность совпадает ли со слотами? |
| Генерация не находит комнату | Проверьте тип, вместимость, features, состояние комнаты и состав группы. |
| Locked class no longer matches | Требование изменено; восстановите его или осознанно снимите блокировку. |
| Личное расписание пусто | Есть ли публикация, связь группы/активный профиль и занятия в выбранной дате? |
| Обновлён черновик, студент видит старое | Это правильно до новой явной публикации. |
| Неделя пустая | Teaching period выбранной версии, фильтры, Day/Week и фактические дни занятий. |
| Ошибка 401 | Токен отсутствует/истёк либо роль/email изменились; войдите снова. |
| Ошибка 403 | Операция не разрешена этой роли; не лечите её раскрытием админских данных. |
| Генерация 503 по времени | Ограничение 10 секунд; уменьшите набор. Это не доказательство неразрешимости. |
| Мобильная неделя широкая | Прокрутка внутри календаря ожидаема; используйте Day. Весь документ не должен уезжать горизонтально. |

При неожиданной ошибке соберите: роль, точные шаги, параметры и выбранную дату, HTTP-статус/текст, количество и ID до/после. Не исправляйте тест удалением базы, отключением проверки ролей или изменением ожидаемого результата без анализа.
