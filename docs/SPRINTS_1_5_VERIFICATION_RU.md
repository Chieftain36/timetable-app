## Уровни доказательств

- `test_app.py`, `test_manual.py`, `test_security.py`, `test_auth_lifecycle.py`: часть кейсов использует fake database; отдельные явно названные live-кейсы используют настоящий PostgreSQL, в том числе конкурентные записи и старую схему.
- `test_planning.py`: интеграционные кейсы используют отдельные PostgreSQL-схемы; чистые тесты алгоритма базы не требуют. Проверяется повторное применение миграции `004_planning.sql`.
- Новый `test_sprints_acceptance.py`: четыре реальных PostgreSQL/ASGI HTTP-кейса. Это не браузерные тесты.
- Расширенный `tests/planning_live_browser.cjs`, запускаемый из Python: настоящий Chromium → локальный Uvicorn/FastAPI → PostgreSQL, без перехвата API. Пароли синтетических аккаунтов задаются только для теста. Вход больше не обходится вставкой JWT в localStorage.
- `npm test`: реальный код фронтенда в Chromium, но ответы HTTP подставные. Этот уровень подтверждает UI-поведение, а не корректность SQL.

## Найденные проблемы и оставшиеся ограничения

1. **Исправлено:** README указывал 100 мест для лекционной аудитории, хотя рабочий предел API/UI/PostgreSQL — 70. Поведение приложения не менялось.
2. **Предупреждения зависимостей:** passlib использует устаревающий Python-модуль `crypt`; в legacy-генерации используется устаревающее имя HTTP 422. Ошибок тестов это не вызвало. Текущий Dockerfile использует Python 3.12; перед переходом на Python 3.13 нужна отдельная проверка зависимостей.
3. **Ограничение алгоритма:** генератор жадный, не полный оптимизатор. Отказ на сложном наборе не доказывает математическую невозможность расписания. Проверены сохранность черновика при отказе и ограничение времени; нагрузочный тест масштаба всего университета не выполнялся.
4. **Сеансы:** после изменения email/роли или удаления аккаунта старый JWT отклоняется. Смена только пароля не является механизмом немедленного отзыва всех ранее выданных JWT; отдельного списка отзыва нет. Не следует считать это проверкой полной политики управления сессиями.
5. **Обновление установленного сайта:** рабочая/опубликованная установка и её данные не проверялись. Для существующей базы нужен совместимый исходный уровень схемы и явное применение `004_planning.sql`; повторяемость и сохранность на синтетической базе проверены. Боевой backup/restore не выполнялся.
6. **Не выполнено:** запуск `start.ps1` под Windows/PowerShell, полный Docker Compose build приложения, Safari/Firefox, проверка экранным диктором, внешний аудит безопасности, нагрузочная проверка, заполнение всех 42 ручных сценариев PDF человеком. Эти пункты не обозначены как пройденные.

Приоритет перед использованием с реальными университетскими данными: резервная копия и пробное обновление копии базы, затем короткая приёмка на целевой установке под тремя ролями. Перед ростом нагрузки — проверка генератора на обезличенном реальном объёме. Перед сменой Python — обновление совместимости аутентификации. Это последующие проверки, а не обнаруженные блокирующие дефекты US1–25.

## Изоляция и завершение

Все записи, удаления, генерации, публикации и миграции выполнялись в отдельном одноразовом PostgreSQL-контейнере с вымышленными аккаунтами `@example.com`. Тесты создают и удаляют частные схемы. Рабочие `.env`, базы, тома и внешняя публикация не использовались. Приложение для браузерной проверки слушало только loopback и завершалось тестом.

После проверки одноразовый контейнер и временный файл подключения удалены. В репозиторий включены только тесты, документация, безопасный вывод тестов и синтетические скриншоты. Слияние в `main` и публикация сайта не выполнялись. Откат этого изменения — откат тестов/документации; миграция или откат данных не нужны.
