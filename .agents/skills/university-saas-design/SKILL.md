# University SaaS design
1. Read `AGENTS.md`, actual `index.html` and relevant API before creating design concepts. Map role and user task.
2. Audit navigation, visual hierarchy, typography, color tokens, spacing, tables, buttons and states.
3. When browsing is available, verify 3–5 current professional reference products; cite URLs and transferable patterns. Never claim unverified visual research.
4. Propose 1–3 distinctive design directions with tokens, accessible contrast, responsive behavior and tradeoffs. Get user approval before broad implementation.
5. Preserve existing endpoints, working features and roles; no invented dashboards, synthetic screenshots claimed as real, or 2D images claimed to be interactive 3D.
6. Implement only explicitly approved scope using existing vanilla JS/CSS stack; inspect rendered desktop/tablet/mobile UI and keyboard interaction.
7. Deliver a design brief, implementation plan, verification summary and known limitations.
